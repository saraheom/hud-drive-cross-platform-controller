# HUD Controller v90.35.3.24.2 — U2W v8.24 wire-handshake compatibility

This is an app-side compatibility correction after the 2026-09-20 parked preflight.

Observed field adapter: `v8.24-recent-idr-catchup` on TCP/15332 sends `U2WH2642` and retains a bounded 1.5 MiB recent-IDR spool. The v90.35.3.24.1 app package expected only `U2WH2643`, so every healthy connection was rejected before any H.264 NAL reached the sanitizer/decoder, causing `RECONNECT_DELAY`, high client-session churn, and relay send failures.

Changes:
- Accept both 8-byte wire magics `U2WH2642` and `U2WH2643`. Both use the same `[u32BE length][NAL]` framing.
- Parse either deployed-v8.24 status keys (`recent_anchor_valid`, `recent_spool_bytes`, `recent_spool_nals`, `recent_spool_cap`, `recent_anchor_invalidations`, `client_bootstraps`, `live_idr_bootstraps`, `last_bootstrap_mode`) or later source-revision keys.
- Update regression tests to require dual-wire compatibility.
- No MainVideo capture, VideoToolbox recovery, ambient-light runtime behavior, HUD relay behavior, or U2W firmware image is changed.

No U2W reflash is required when the adapter reports `relay_version=v8.24-recent-idr-catchup` and `wire_magic=U2WH2642`.
