# v90.35.3.24.7 + U2W v8.26 — deterministic MainVideo bootstrap + HUD-internal OBD probe v4

This release is based on v90.35.3.24.6.1 and pairs the iOS app with **U2W v8.26 Persistent GOP Bridge**.

## Field failure addressed

The 2026-09-22 drive proved three specific facts:

1. v8.11 MainVideo capture remained healthy while v8.25 repeatedly lost a usable decoder bootstrap.
2. v8.25 ended with 126 current-file GOP scans / 125 misses and 102 client sessions / 100 client replacements.
3. A successful 20/20 decode could be destroyed by the next ordinary v8.11 rolling-file generation, even though that generation was only a storage rotation in the same CarPlay codec stream.

## MainVideo changes

### U2W v8.26

- Adds wire magic `U2WH2644` with the existing `[u32BE length][NAL]` framing.
- Preserves validated H.264 parser/codec state across ordinary v8.11 file rotation.
- Maintains one coordinated disk-backed validated GOP recovery cache across those rotations.
- Cache is built and replayed by the same native relay process; no v8.21-style separate cache daemon and no long-lived Boa video CGI.
- Cache is not replay-ready until the IDR frame has completed.
- Actual SPS/PPS changes invalidate the cache and begin a new codec epoch; file rotation alone does not.
- A new/recovering client tries persistent GOP cache -> one current-file validated-GOP fallback -> next validated live IDR.
- Cache cap remains 48 MiB; overflow falls back to live-IDR waiting.
- v8.11 capture, Route Guidance, Now Playing and HUD v8.15.1 JPEG relay are untouched.

### iOS v90.35.3.24.7

- Accepts `U2WH2642`, `U2WH2643`, and `U2WH2644`.
- Tracks v8.26 persistent-cache and adapter-source diagnostics.
- In `WAITING_LIVE_IDR` / `WAITING_FRESH_IDR`, byte silence is no longer treated as a reason to reconnect. The same TCP client is retained until a real socket EOF/failure, relay restart, or explicit manual reconnect.
- Adds startup decoder hysteresis: before 10 decoded frames establish steady state, the hard stale-output threshold is 8 seconds and the soft flush is suppressed. This prevents the observed frame-#1 / hard-reset race.
- Once steady state is established, the existing 3-second VideoToolbox stale-output recovery remains active.
- Each decoder-stall episode still gets one bounded adapter recovery-seed replay; if that seed produces no frame, TCP is preserved and the decoder waits for a genuine live IDR.

## OBD speed investigation v4

The prior v3 runs, including a 1–44 mph sample, found no usable phone-facing speed field and no `41 0D`/ASCII `410D` response. v4 therefore moves below that packet layer.

New Map Mode diagnostics:

- **Run 90 s HUD-internal OBD probe v4**
  - starts while parked, then runs during normal driving;
  - uses the existing HUD-managed OBD connection only;
  - repeatedly stimulates hidden stock `OBD_DRIVING_VELOCITY` every 5 seconds;
  - records GPS min/max speed and MainVideo state to a shareable manifest;
  - does not replace the visible GPS speed and does not open a second iPhone→OBD link.
- **Collect HUD OBD logs (parked)**
  - requests up to five recent `LOG_CATEGORY_OBD` files after the road phase;
  - reuses the existing hardened diagnostic ZIP/raw BLE capture path;
  - intended offline targets include `010D`, `410D`, ELM `AT` traffic, HUD internal speed values, service/native logs, or other clues to the stock OBD speed source.

## Recommended road validation

1. Flash U2W v8.26.
2. Install app v90.35.3.24.7.
3. With the car parked, establish CarPlay and start navigation.
4. Wait for `LIVE • 20s continuity verified` and verify the MainVideo frame counter continues increasing.
5. Use Map Mode at 10 fps for the first v8.26 road test.
6. While still parked, start **OBD HUD-internal probe v4**, then drive normally for at least 90 seconds.
7. Continue the MainVideo/Map Mode test for the rest of the drive, including a navigation stop/restart if convenient.
8. At destination while still powered and parked, tap **Collect HUD OBD logs (parked)**.
9. Share the normal HUD log, U2W status/dump files, OBD v4 manifest, diagnostic ZIP and raw diagnostic capture if produced.

Road validation is still required; this release is specifically designed around the observed failure mechanisms and does not claim unrelated HUD Wi-Fi STA or viewer issues are solved by the MainVideo changes.
