# HUD Controller v90.35.3.24.36 — Persistent OBD Recovery + Preset Reset Safety

## Base and scope
Full GitHub repository derived from v90.35.3.24.35, retaining working automatic Map Mode startup, Keep decoder + BG task, native startup-message transmitter, ETA rendering, and existing Siri/App Intents fixes. U2W v8.40 firmware payload/source remains unchanged; **no firmware update** required. No MapKit fallback added.

## 1. Direct OBD speed recovery while physical Map Mode is active
- Map Mode continues using **fresh 41 0D OBD speed at 5 Hz** whenever available. GPS is the live fallback only while OBD is unavailable/stale; it is never preferred over fresh OBD.
- A session-scoped CoreBluetooth recovery task retries connection to the previously selected ELM327 and alternates with bounded BLE scans; retries continue while Map Mode owns the adapter, rather than ending after a single scan.
- The watchdog detects a connected adapter that has stopped returning valid speed data for over 8 seconds and a GATT discovery that stalls for over 15 seconds; it requests a bounded reconnect. It also cancels a BLE connect that hangs for over 15 seconds, with late-connect rejection protection.
- The polling loop now has a generation token so cancellation from an old BLE session cannot clear the state of a newer polling task.
- Recovery cancels as soon as Map Mode releases direct OBD ownership, preserving the release barrier and HUD's normal Free Ride/Navigation OBD reconnection. Never sends ELM ATZ/ATSP or any protocol-reset commands.
- New `OBD RECOVERY` logs distinguish watchdog start, retries, stale-response reconnect, scan, timeout and stop. UI status identifies GPS backup during recovery.

**Important**: On an unavailable adapter, current GPS speed remains the *safe live fallback* rather than displaying an indefinitely stale OBD reading. No speculative stationary GPS clamp was added.

## 2. Native HUD startup-message verification

- Added **Test stock HUD message (parked)** under Custom Map Mode. Available only with HUD BLE connected while physical Map Mode is not active. Does not use Music, modify notification filters, or change HUD display mode.
- If the physical HUD still shows nothing during this parked test, the native firmware renderer/packet mapping needs additional validation; no assertion is made that it displays.

## 3. Map Mode Preset 2 preservation and safe reset
- Existing saved presets and active preset migration keys are unchanged. Upgrading **does not replace or overwrite Preset 2**.
- `Reset selected position`, `Reset all positions`, and `Restore pre-designer layout` now require an explicit SwiftUI destructive action confirmation. Buttons moved into a separated `Layout reset tools` section below the size slider.
- Before any confirmed reset, saves the COMPLETE active visual-preset snapshot (not only position offsets) in per-preset UserDefaults storage, making **Undo last reset (Preset N)** available even after restarting the app. The undo is one-shot and isolated to the selected preset.
- The October 20 drive log recorded runtime data but did not capture the complete historical Preset 2 snapshot, so it cannot reconstruct the exact settings lost before this update. There is no forced restoration or invented values.
