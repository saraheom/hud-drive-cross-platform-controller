# HUD Controller v90.35.3.24.22 + U2W v8.35 Release Notes

## Scope

This paired release addresses the two findings from the October 3 field drive without reopening the v8.34 mirror/relay design that behaved correctly in the field.

1. **MainVideo lifecycle recovery** — the prior drive showed `kVTInvalidSessionErr (-12903)` during an iOS scene transition while TCP/15332, the v8.34 mirror, and Route Guidance remained healthy. v24.22 therefore preserves the raw H.264 transport but intentionally retires VideoToolbox during `inactive/background`, rebuilding only after the scene is stably active. An invalid-session event uses the same bounded recovery path.
2. **Bounded native keyframe request** — U2W v8.35 adds a minimal ARM helper/CGI that emits a single Carlinkit `RequestKeyFrame` message (`type 0x0C`, zero payload), subject to adapter-side and app-side cooldowns. It does not reconnect MainVideo TCP or signal/restart AppleCarPlay/ARMiPhoneIAP2.
3. **Direct ELM327 coexistence probe** — the Vehicle page can scan/select/connect to a BLE ELM327 candidate while leaving the HUD's existing OBD ownership untouched. An explicit one-shot `01 0D` probe can then test whether a simultaneous iPhone/HUD connection is viable. Production Map Mode speed remains GPS.

## MainVideo changes

- U2W v8.34 hard-bounded lossless mirror is unchanged.
- Exact v8.31 32-KiB raw TCP relay is unchanged.
- `inactive/background` keeps the TCP/H.264 source alive but invalidates only the VideoToolbox session.
- Foreground decoder reconstruction waits for a short stable-active interval instead of recreating during a scene transition.
- `kVTInvalidSessionErr (-12903)` is treated as decoder-session loss, not as proof of adapter-stream corruption.
- Startup waiting-for-IDR and invalid-session recovery may issue one bounded keyframe request; cooldown prevents request loops.
- Physical Map Mode fallback remains available while live decoding is unavailable.
- Route Guidance and Now Playing remain independent.

### Keyframe-request safety boundary

U2W v8.35 is an incremental layer over v8.34. The installer verifies the exact active v8.34 mirror and exact v8.31 relay before installing only:

- `/usr/bin/u2w_request_keyframe`
- `/usr/share/u2w/cgi-bin/u2wvideo-request-keyframe.cgi`
- updated MainVideo status CGI/marker telemetry

The helper sends one 16-byte request:

`AA 55 AA 55 00 00 00 00 0C 00 00 00 F3 FF FF FF`

It tries `/var/run/adb-driver` once and, only if that send fails, `/var/run/phonemirror` once. There is no retry loop, process restart, process signal, source-FD reacquisition, or TCP reconnect.

**Field-validation note:** the request type/header is verified against the known Carlinkit protocol, but the exact local Unix-datagram injection route on this 2021.03.06.1343 adapter has not yet been proven by a drive. The next field test must confirm that the request causes a fresh SPS/PPS/IDR without requiring reverse.

## Direct ELM327 feasibility probe

The new `Direct OBD / ELM327` block is diagnostic-only.

- BLE scan is bounded.
- Selecting a discovered peripheral automatically attempts a direct iPhone connection.
- The HUD is not proactively disconnected; this tests true coexistence first.
- All discovered services/characteristics and notify/write properties are logged.
- The only OBD command sent is an explicit user-triggered `010D\r`.
- No `ATZ`, `ATSP0`, reset, or protocol-selection command is sent.
- A valid response must contain `41 0D XX`; `XX` is interpreted as km/h and compared with GPS.
- HUD OBD-connected state is logged before and after the iPhone connection/probe.
- ELM scan/connect/GATT/TX/RX/speed evidence is written into the existing HUD log and Live Map Diagnostic timeline; no new standalone ELM log package is required.
- Production displayed speed remains GPS in this release.

If simultaneous ownership is not supported, one clean failure/disconnect observation is enough. Do not repeatedly reconnect during a drive. A future build can implement the already-discussed ownership handoff (iPhone owns OBD only in Map Mode; HUD owns it in Navigation/Freeride) if needed.

## First field test

1. Flash v8.35 over the currently installed v8.34 baseline and allow the normal updater reboot.
2. Run v24.22 and start navigation/Map Mode normally. **Do not intentionally reverse at startup.** The first question is whether the bounded keyframe request yields a fresh SPS/PPS/IDR on its own.
3. If MainVideo becomes live, leave it running normally and observe whether a scene/lifecycle transition can recover without reverse.
4. For Direct ELM testing, open the Vehicle page, scan BLE, select the OBD/ELM candidate, and observe whether both the iPhone connection and HUD OBD state remain connected. Only when safely parked, use the one-shot `01 0D` speed probe.
5. If MainVideo or ELM behavior is unexpected, collect the normal HUD log and **Live Map Diagnostic ZIP**. The ELM evidence is already included there.
