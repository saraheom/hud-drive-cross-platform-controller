# HUD Controller v90.35.3.24.9 + U2W v8.28 — safe MainVideo source reacquisition

This paired release targets the 2026-09-23 field failure in which the live CarPlay map remained in `WAITING_LIVE_IDR`, became live immediately after the Nissan display left and re-entered CarPlay, and then failed again one to two minutes later. The same capture showed VideoToolbox `codecBadDataErr (-8969)`. The working hypothesis is therefore no longer a TCP/cache problem: the passive MainVideo mirror can remain attached to an outbound fd that is no longer carrying a trustworthy 800×480 H.264 reference chain across CarPlay display/focus lifecycle changes.

## U2W v8.28: conservative automatic source reacquisition

v8.28 keeps the existing v8.11 AppleCarPlay wrapper model but replaces the fixed-source assumption with a deliberately constrained selector plus a standalone full validator.

- The real `write` / `send` / `writev` / `sendmsg` call completes before observation.
- Selector synchronization is a non-blocking try-lock; contention skips observation rather than blocking an AppleCarPlay media thread.
- The selector performs no status formatting, rename, or logging writes in the media hot path.
- A replacement fd is promoted only after bounded SPS -> PPS -> IDR proof.
- The standalone relay performs the heavier H.264 validation, including the expected 800×480 SPS geometry and slice/reference checks.
- If 2 MiB of mirror data advances without a fully validated VCL chain, the relay creates one tiny reselect request. The selector checks for that request only once every 64 observed calls, invalidates only its source association, and resumes bounded candidate observation.
- `AppleCarPlay` is never killed, signaled, restarted, or fed modified/injected CarPlay bytes.
- If no replacement stream proves itself, nothing is promoted; the recovery remains passive.

This is intended to reproduce the *useful video-source reacquisition* that the OEM-screen transition exposed without requiring the driver to leave and re-enter the CarPlay screen.

## Source-epoch fencing

The v8.28 relay uses `U2WH2646` on TCP/15332. Every mirror truncation/replacement is a codec-epoch boundary. Parser state, SPS/PPS, and client-live state are reset, and downstream video resumes only at a fresh validated SPS/PPS/IDR sequence. There is no historical GOP replay and no persistent GOP cache.

## iOS v90.35.3.24.9

- Accepts the v8.28 `U2WH2646` relay.
- Treats VideoToolbox `codecBadDataErr (-8969)` as source-epoch corruption rather than repeatedly rebuilding against the same reference chain.
- Preserves the TCP connection but clears sanitizer and decoder SPS/PPS state and requires a fresh SPS -> PPS -> IDR epoch.
- Extends the parked MainVideo continuity target from 20 seconds to 5 minutes because the 9/23 field failure passed the old 20-second validation before failing shortly afterward.

## OBD diagnostic ZIP

Manual `Collect/reconstruct HUD OBD ZIP (parked)` no longer uses GPS speed as a gate. A stale/non-zero GPS reading can therefore no longer prevent collection after the vehicle is physically parked. HUD BLE must still be connected and no diagnostic transfer may already be active. The 90-second v4 road probe is not required for this archive-collection test.

## Intentionally unchanged

- Ambient-light production behavior
- Door speed-warning animation/brightness restore behavior
- Route Guidance provider priority and normal navigation semantics
- v8.15.1 physical HUD JPEG wire protocol
- Now Playing behavior
- Speed-limit matching logic

## First validation

1. Upload U2W v8.28 while parked.
2. **Fully remove power from the adapter and reconnect it.** A Wi-Fi reconnect alone cannot load the new selector into an already-running AppleCarPlay process.
3. Verify `u2wvideo-status.cgi` reports the v8.28 selector and `u2wvideo-relay-status.cgi` reports `relay_version=v8.28-safe-fd-reacquire` / `wire_magic=U2WH2646`.
4. Install v90.35.3.24.9 from the iOS CI build.
5. Use 10 FPS for the first test.
6. Start Google Maps while parked and deliberately **do not** leave the CarPlay screen. The extended target is `LIVE • 5m continuity verified`.
7. Drive normally. A source starvation/reacquisition should be automatic; the driver should not need an OEM-screen switch.
8. After arriving and physically parking, tap `Collect/reconstruct HUD OBD ZIP (parked)`. No GPS-speed gate is applied.

Field validation is still required. The implementation is intentionally biased toward doing nothing rather than forcing an unproven source switch, and it does not claim that undocumented adapter internals can be proven crash-free before road testing.
