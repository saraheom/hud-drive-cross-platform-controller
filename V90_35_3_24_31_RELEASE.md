# HUD Controller v90.35.3.24.31 + U2W v8.40 Resource-Safe Background Probe

This release prepares a clean, interpretable **Hardware Decoder + BG Task** lock-screen test without allowing the bootstrap experiment to exhaust U2W `/tmp` or damage Route Guidance state.

## App changes

- Background probe selection is now **staged**. Tapping Baseline / Keep Decoder / Hardware Decoder / Suspend Decode only selects the next mode.
- A separate **Apply for next Map Mode session** button commits the selected mode.
- Apply is blocked while physical Map Mode or the app-only live preview is active, so selecting a decoder backend cannot rebuild VideoToolbox mid-drive.
- The probe panel now displays the full decoder state, including `backend=hardware|software` and `hwRequested=0|1`.
- Startup snapshot fetching is **single-flight**. A second bootstrap request joins the active fetch instead of launching another current/previous snapshot pair.
- Foreground/lifecycle rebootstrap is protected by a 6-second cooldown. Duplicate recovery triggers are logged as suppressed rather than restarting the worker repeatedly.
- Diagnostic ZIP collection now includes `u2wresource-status.cgi` and records both active and pending probe modes.

## U2W v8.40 changes

- Replaces the v8.38 per-request snapshot copies with **zero-copy pinned-inode streaming**:
  - current generation: two read-only descriptors pin the same current mirror inode, one for SHA and one for the fixed-length body;
  - previous generation: the existing bounded retained file is pinned and SHA-validated without creating another H.264 copy.
- No `u2w_v838_bootstrap_current_$$.h264` or request-scoped previous-generation H.264 file is created.
- Installer removes leaked legacy v8.38 request temp files.
- Route Guidance and Now Playing JSON publication is fail-closed:
  - the entire payload must be written successfully before rename;
  - short/failed writes delete only the temporary file;
  - the last known-good published JSON is preserved.
- RGD diagnostic append files rotate at 512 KiB each so binary/log captures cannot grow without bound.
- Adds `/cgi-bin/u2wresource-status.cgi` with tmpfs usage, legacy-bootstrap-temp counts, and RGD publication failure counters.
- `u2wvideo-relay-status.cgi` now also reports v8.40 resource-safety state and free tmpfs.

## Preserved paths

The following proven components are unchanged:

- v8.34 hard-bounded MainVideo mirror
- exact v8.31 raw relay lineage
- v8.38 passive previous-generation observer/base history mechanism
- v8.39 HUD helper/session-boundary recovery
- v90.35.3.24.28 H.264 sanitizer/quarantine logic

## Recommended Hardware Decoder test

1. Install the app and U2W v8.40, then restart the adapter.
2. Keep Map Mode **off**.
3. In **Map Mode Background Continuity Probe**, select **Hardware decoder + BG task**.
4. Tap **Apply for next Map Mode session**.
5. Enable Map Mode.
6. Before locking the phone, confirm the decoder line shows `hwRequested=1`. Ideally it should also show `backend=hardware`; if iOS declines hardware acceleration it will say `backend=software`.
7. Lock the phone and observe whether the HUD map continues.
8. At the end of the test, collect the Background Probe / Live Map diagnostic ZIP.

This release does not assume Hardware Decoder + BG Task will survive iOS lock. Its purpose is to make that test valid and resource-safe.
