# HUD Controller v90.35.3.24.30 + U2W v8.39

## Scope
This release keeps the field-proven v24.28 mid-drive H.264 continuity/sanitizer path unchanged and layers four targeted fixes plus an explicit iOS background-continuity experiment block.

### Map Mode Background Continuity Probe
The Map Mode page now exposes one mutually-exclusive probe mode at a time:
- **Baseline** — v24.29 lifecycle behavior.
- **Keep decoder + BG task** — requests the finite iOS background assertion before leaving foreground and keeps the software-preferred VideoToolbox decoder fed while iOS permits execution.
- **Hardware decoder + BG task** — same assertion, but new decoder sessions request hardware acceleration. The app queries `kVTDecompressionPropertyKey_UsingHardwareAcceleratedVideoDecoder` and records whether hardware was actually granted.
- **Suspend decode + preserve stream** — gates VCL decode in background while preserving transport/parser activity; on foreground return the iPhone worker is recreated using the proven v8.38 read-only snapshot/live-edge bootstrap.

A separate **Prevent Auto-Lock while Map Mode is active** toggle controls the iOS idle timer. Manual phone locking remains possible. The existing Live Map ZIP recorder is also available directly as **Collect Background Probe ZIP**.

Changing into or out of the hardware probe while MainVideo is already running performs an iPhone-only read-only rebootstrap so the requested backend applies immediately. No AppleCarPlay or adapter MainVideo process is restarted.

## ETA/lane arbitration
Map Mode now carries a dedicated `laneGuidanceVisible` state derived from the provider's live `laneGuidanceShowing` flag. Cached lane vectors may remain available for continuity, but they no longer suppress ETA after the provider hides the lane event.

With **Use lane-guidance position for ETA when lanes are unavailable** enabled:
- live lane event visible -> lane arrows render; ETA is absent;
- lane event not visible -> ETA renders at the exact lane block coordinate.

## ETA AM/PM removal
AM/PM stripping now normalizes Unicode narrow no-break space (`U+202F`) and no-break space (`U+00A0`) and splits on Unicode whitespace. This covers CarPlay/Google Maps strings such as `6:35 PM` when AM/PM is disabled.

## U2W v8.39 session-boundary recovery
v8.39 is layered on top of v8.38 and deliberately does **not** modify the v8.34 MainVideo mirror, v8.31 raw H.264 relay, or v8.38 read-only startup snapshot.

Two narrow adapter session fixes are added:
1. Every new physical Map Mode start retires and recreates only the three custom HUD helpers (frame ingress, discovery, MJPEG cast relay). Stale helper PIDs are never reused across a new Map Mode session.
2. The Route Guidance preload treats a new Wi-Fi Identify after a progressed/accepted prior session as a new CarPlay/iAP2 session. It clears only Route Guidance negotiation/cache state and re-arms 0x5200 negotiation. AppleCarPlay is never signaled or restarted.

The v8.39 preload is ARMv7 EABI5 and installation requires the exact v8.38 baseline Route Guidance preload SHA-1 plus the v8.38 marker. Rebooting the adapter after installation is required so the new preload is mapped into the iAP2 process.

## Safety boundaries preserved
- v24.28 `H264MainVideoSanitizer.swift`: byte-for-byte unchanged.
- v8.34 MainVideo mirror: unchanged.
- v8.31 raw TCP/15332 relay: unchanged.
- v8.38 startup bootstrap snapshot path: unchanged.
- No U2W v8.39 script signals/restarts AppleCarPlay or MainVideo.
- Navigation remains independent/fail-safe.
