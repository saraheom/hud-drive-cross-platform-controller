# HUD Controller v90.35.3.24.45 — offline-first Philadelphia OSM matching

Based on **v24.44**. This release changes **Current + Nav** only; the user-selectable original **Current** remains the unmodified baseline. No U2W firmware, BLE/OBD, H.264/video recovery, map rendering, approved U-turn, or roundabout graphics changes.

## Why this architecture is different

Field logs for v24.44 showed only 83 of 262 route-active samples with a speed-limit sign (31.7%), chiefly because incoming public Overpass responses took 25–40 seconds or failed. The matcher correctly selected named roads when geometry and tags were available. Merely increasing an HTTP timeout cannot make a continuously moving car stay inside a 400m downloaded area.

## What changed

- **Build-time OSM-derived Philadelphia road map:** `tools/build_philadelphia_osm_bundle.py` downloads a geographically bounded extract of the public **OSM Roads Philadelphia** ArcGIS service (published May 2026), containing named road geometry and available explicit numeric `maxspeed` values. This is **not** the separate City of Philadelphia speed-limit GIS. The data is from OSM, published through an ArcGIS FeatureServer, with km/h numeric speeds. No road-class or 25 mph default is inserted. ODbL/OSM attribution accompanies the app.
- **Embedded offline index:** `CurrentNavOfflineOSMIndex.swift` validates the generated JSON, builds a ~400m-cell spatial index, and returns nearby road ways. The app reads/builds the index on a utility-priority detached task, rather than blocking the HUD's 12–15fps rendering actor.
- **Offline + online merge:** `OriginalSpeedLimitEngine.swift` combines locally indexed roads with geographically applicable previously cached or freshly fetched Overpass ways. Online ways take precedence for matching OSM IDs. The unchanged road-identity policy still requires a **matching CarPlay Current Street**, perpendicular GPS-to-road distance, and heading agreement. An adjacent Schuylkill Expressway is not an eligible substitute for MLK Drive. Missing tags remain unknown and the speed sign stays hidden.
- **Safety and warnings:** An offline-only limit may be displayed with its road identity confirmed, but **never arms an overspeed warning** merely because it came from the offline snapshot. The existing live-verification requirement for warnings remains.
- **Outside the Philadelphia snapshot:** The original Current + Nav online Overpass requests, local caching, and named-road audits remain available. No additional hardware or U2W flash is needed.
- **CI/build safeguard:** The GitHub **iOS 26 TestFlight**, standard iOS TestFlight, and ad hoc release workflows generate the full map **before XcodeGen** and fail if it is incomplete. TestFlight also inspects the archive to ensure the actual populated map resource is embedded. The regular iOS CI workflow exercises source/tests but does not need to access the public GIS server.

## Critical build-time caveat

**This source ZIP does not contain the complete Philadelphia map.** It contains an intentionally empty JSON placeholder plus the generator. The real dataset must be fetched during a release workflow. Since the assistant's container cannot reach the GIS service, live dataset availability, the remote ArcGIS server response, and the XcodeGen resource-copy step **cannot be confirmed locally**. The release workflow explicitly fails rather than silently distributing the placeholder. Do not deploy a build that does not log `OFFLINE_BUNDLE_READY` and have the verified archive resource.

The OSM-derived published layer may be older than recent road signage and may omit `maxspeed` even when a legal limit exists. Its existence does not guarantee 100% accurate signs. The display is supplemental and does not replace posted signs.

## Validation completed before release

- Local Python regression suite including native Swift offline spatial index + semantic/geometry matcher fixture, prior MLK-vs-expressway regression, and request/audit tests.
- Native Swift `CurrentNavOfflineOSMIndex` compiled and ran with three synthetic roads: tagged Ridge Avenue, tagged Schuylkill Expressway, and untagged River Ridge Court. A closer expressway cannot satisfy a mismatched street name; an untagged road does not acquire a limit.
- Previous Original Current engine functions and all U2W, OBD, video, and maneuver assets unchanged by this version.
- Source parsing, YAML parsing, and archive integrity checks reported in the adjacent build verification report.

## Installation and next drive

1. Upload the **complete repository ZIP** to the GitHub project and run **iOS CI**.
2. Run **iOS 26 Ambient TestFlight**; it downloads the Philadelphia OSM snapshot, validates it, generates XcodeGen, and verifies inclusion in the archived app. Review the `Build verified offline Philadelphia OSM road snapshot` step for the number of roads and explicit speed tags.
3. On launching the app, look for `OFFLINE_BUNDLE_READY roads=... tagged=...`; with **Current + Nav** selected, look for `OFFLINE_MERGED`, `ACCEPT ... evidence=direct_OSM` and `UNKNOWN ... untagged=1`.
4. Compare any displayed speed with actual posted signs, particularly MLK Drive, Ridge Ave, N 34th Street, Kelly Drive, and near highway entrances. The roundabout remains untested; U-turn artwork is final and unchanged.
