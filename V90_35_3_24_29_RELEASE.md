# HUD Controller v90.35.3.24.29 + U2W v8.38

## Scope

This paired release keeps the successful v24.28 mid-drive H.264 continuity protections and v24.27 HUD-viewer re-entry fix intact, then addresses the next three field issues:

1. startup commonly waits for a fresh IDR until reverse or Nissan-menu -> CarPlay forces a new encoder bootstrap;
2. switching away from the HUD Controller app can interrupt live Map Mode even though ordinary scene-inactive transitions no longer intentionally destroy VideoToolbox;
3. Map Mode's newer per-component designer was still layered on top of the historical left/center/right parent layout, so phone-preview positions such as ETA could not map faithfully to the physical 480x240 HUD.

## Startup bootstrap: v8.38 read-only history + continuous live bridge

U2W v8.38 adds a passive, read-only startup-history sidecar. It does **not** replace the v8.34 hard-bounded mirror, the exact v8.31 raw TCP/15332 relay, or the v8.35 helper, and it never signals/restarts AppleCarPlay or Route Guidance.

At adapter boot, a small observer waits for the existing `/tmp/u2w_mainvideo_live.h264` mirror and retains the immediately previous complete 8 MiB generation across normal atomic rotation. Two read-only CGI endpoints expose the retained previous generation and a stable copy of the current generation.

The iPhone startup sequence is deliberately continuity-safe:

1. confirm/start the unchanged v8.31 TCP/15332 relay;
2. attach the live TCP client **before** fetching snapshots and buffer its raw live-edge bytes;
3. fetch a rotation-stable current snapshot, then the retained previous snapshot;
4. prove an exact byte overlap between the end of the current snapshot and the buffered live TCP bytes;
5. use U2W generation metadata to prepend the retained previous snapshot **only** when it is proven to immediately precede that exact current generation;
6. feed the proven-continuous history through the existing iPhone Annex-B parser/sanitizer/VideoToolbox pipeline and continue from the first non-duplicated buffered live byte;
7. if overlap or previous/current generation coherence cannot be proven, discard the unsafe portion and safely continue with current+live or the old `WAITING_LIVE_IDR` behavior.

This closes the transfer-time gap that would otherwise exist between a snapshot and a relay that starts at the live edge. The adapter still performs no H.264 parsing.

The bootstrap is best-effort rather than a process-control hack: if the initial SPS/PPS/IDR is older than the retained previous+current history, startup can still wait for a natural fresh IDR. Field validation is therefore still required before claiming reverse/menu switching is eliminated in every startup timing case.

## Short app-switch/background continuity

While Map Mode/MainVideo is active, entering the background now begins a bounded iOS background task named `HUD Map Mode continuity`. Ordinary scene inactive/background transitions continue preserving:

- raw TCP;
- Annex-B parser state;
- VideoToolbox session;
- SPS/PPS and H.264 reference chain;
- HUD JPEG relay state.

Returning active ends the background task without a proactive decoder rebuild, sanitizer quarantine, or fresh-IDR requirement. A genuine VideoToolbox invalid-session/error path remains authoritative and still uses the existing bounded recovery mechanisms.

This is intended to protect short excursions into another app. iOS controls background execution and may suspend arbitrary app work after the granted background interval, so indefinite live video processing while another app remains foreground is not guaranteed.

## Map Mode full-canvas layout

The active Map Mode renderer no longer uses the old 20% left / 58% center / 22% right parent `HStack`. It renders on one canonical **480x240** canvas. The same final coordinates are used by the customization preview and the physical HUD image.

These components are individually positionable across the canvas:

- speed;
- speed-limit sign;
- map;
- turning street;
- maneuver arrow;
- distance;
- lane guidance;
- ETA;
- Time Left.

Existing preset positions are migrated approximately by folding old offsets into each component's initial anchor. Legacy left/center/right placement controls are no longer presented in the active customization UI. Existing map fades and per-component styling controls remain available. Map Mode FPS remains **5 / 8 / 10 / 12 / 15**; 20/25 fps were intentionally not added.

## ETA shares lane-guidance position

A persisted toggle is added:

`Use lane-guidance position for ETA when lanes are unavailable`

When OFF, ETA and lane guidance remain independent blocks.

When ON:

- actual lane guidance available + lane guidance enabled -> lane arrows render at the Lane Guidance position and ETA is hidden;
- no lane guidance available -> ETA renders at the Lane Guidance position;
- `Show Lane Guidance` disabled -> ETA can occupy the shared location continuously;
- `Show ETA` disabled -> no fallback ETA is rendered;
- Time Left remains independent.

While the shared-position toggle is ON, ETA is removed from the movable-component selector because its standalone position is not used; move the Lane Guidance component to set the shared location.

## Preserved reliability work

The v24.28 generalized one-picture H.264 continuity quarantine is byte-for-byte unchanged from the validated v24.28 baseline. The v24.27 staged decoder recovery and current-viewer health behavior remain. U2W v8.38 does not alter any earlier U2W directory or proven mirror/relay binary.
