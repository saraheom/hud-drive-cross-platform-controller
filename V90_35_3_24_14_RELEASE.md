# v90.35.3.24.14 — Navigation-Priority Raw MainVideo

Paired adapter: **U2W v8.31 Navigation-Priority Raw MainVideo Relay**.

## Safety architecture

Navigation Mode is independent of MainVideo by construction:

- app launch does **not** start MainVideo;
- HUD BLE connection does **not** start MainVideo;
- Route Guidance reachability does **not** start MainVideo;
- U2W v8.31 has **no MainVideo boot/autostart hook**;
- the raw video relay starts only after an explicit Map Mode request;
- if no real CarPlay frame decodes within the bounded Map Mode startup window, the HUD stays in stock Navigation Mode and the raw relay is stopped;
- if an active Map Mode stream becomes stale or the app backgrounds, the app restores stock Navigation and stops all experimental video work.

The existing v8.8 Route Guidance / lane / Now Playing path and the exact v8.11 AppleCarPlay exporter are not modified.

## Why v8.31 differs from v8.30

v8.30 used an always-running adapter-side semantic H.264 parser plus a 12 MiB complete reference-chain spool. v8.31 removes that architecture entirely. The adapter component is a single-client raw-byte relay with a 32 KiB fixed buffer and no H.264 parsing, SPS/PPS/IDR bookkeeping, GOP/reference cache, historical replay, or hot-path status writes. All H.264 semantic work runs on the iPhone.

## Field-failure fixes

- Physical HUD health no longer treats a missing BLE STA-status reply as proof a proven current U2W viewer is dead.
- A pending VideoToolbox rebuild is no longer cancelled merely because compressed AU submission succeeded; recovery must be proven by a successful decoded-image callback.
- MainVideo TCP failure/source stall is fail-closed for v8.31; no automatic relay/reconnect storm is used.
- Existing sequence-1428 moving/near-turn Route Guidance stale-snapshot protection is retained unchanged.

## Scope intentionally unchanged

Ambient light automation, HUD Bluetooth/OBD transport, Map Mode drawing/layout, Route Guidance parser, and Now Playing client remain byte-identical to v90.35.3.24.13.1 where applicable.
