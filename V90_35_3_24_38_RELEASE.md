# HUD Controller v90.35.3.24.38 — Current + Nav road-identity fix / OBD session cleanup

Base: **v90.35.3.24.37** full GitHub repo. This is an **iOS-side-only** release. U2W **v8.40** remains unchanged. There is no adapter firmware image to flash.

## Why this build

The October 22 drive log (`HUD_2026-10-22_12-55-02.log`) recorded the *incorrect* Schuylkill Expressway 50-mph limit when Google Maps supplied `Sweetbriar Dr`, `Martin Luther King Jr Dr`, and earlier `N 34th St`. The v24.37 `Current + Nav` code applied only a 0.6 scoring bonus for matching street names. The old HUDWAY road acceptance geometry could also admit the expressway at large distances, and the Overpass request ignored untagged roads completely.

## 1. Correct road identity before using its speed limit

- **Current** is unchanged: original 400m maxspeed-only Overpass query, original HUDWAY geometry acceptance/scoring, and original speed warnings.
- **Current + Nav** now has its own 430m Overpass query for **all motorable OSM road segments, including segments with no maxspeed tag** (no Philly GIS). Nonmotor vehicle paths are excluded. It refreshes on movement with 75s cache age, reuses good responses within the bounds, and has a bounded 18s backoff on failures.
- With fresh CarPlay `currentRoad`, only road geometries whose OSM name/reference **matches the normalized Current Street** can provide a speed limit. A nearby differently named motorway is **not eligible**, regardless of distance score or maxspeed availability.
- The new `CurrentNavRoadMatchPolicy.swift` implements **true perpendicular distance to finite OSM segments** and a bounded 20–34m accuracy-aware corridor. When moving, road heading must also be within 65° of travel direction (forward or reverse); at low speed, heading is not used as a gate. The old HUDWAY endpoint-circle geometry remains intact **only in Current**.
- First select a GPS-plausible, name-matching road *even if that road is untagged*. Resolve speed from that way's explicit `maxspeed`. If that way is untagged, optionally use **unanimous explicit speed tags** on connected (endpoint gap <=12m), name-matching pieces within 200m. Conflicting/missing speed evidence => **unknown**, **not** an adjacent road's value. Connected-road speed is display-only, not overspeed-warning eligible.
- The app immediately clears the previous sign and warning on a CarPlay current-street change. An unavailable speed produces an unknown limit; a previously verified same-road value can be held up to 12s / 150m **display only**, with warnings off. A CarPlay heartbeat outage up to 10s does not trigger an immediate geometry-only highway takeover. Once route information is no longer available, Current + Nav returns to the original baseline matcher.
- More explanatory `SPEED CURRENT NAV`, `SPEED CURRENT NAV QUERY`, and `SPEED CURRENT NAV ROAD` lines report decision, top alternatives with approximate distance/name agreement, road class, selected posted speed, and warning eligibility. HTTP response code is included for non-2xx query failures.

### Road-matching caveats

Current Street is road identity, **not the legal speed**. This build does not guess 25 mph based on a road name or road class. If the corresponding OSM posted speed is absent or conflicting, the speed-limit sign can remain unknown. Near poorly mapped intersections, navigation may update the street name before GPS geometry reaches the new road; this will temporarily suppress a limit, by design. Verify posted signs and obey local regulations. Source/route confidence was checked against a recorded *failure pattern* and synthetic test geometry, **not** by replaying full external OSM map responses from the October 22 drive.

## 2. Stop OBD recovery when the HUD BLE session ends

- Physical HUD BLE disconnect immediately cancels the iPhone Map Mode handoff task and releases the direct ELM327 manager's session ownership. This cancels the continuous recovery watchdog and invalidates stale BLE callbacks.
- Clear the HUD OBD controller's temporary ownership-suspension flag **without issuing commands to a disconnected HUD**. The existing rehydration path can return to the user's saved OBD auto-connect preference when the HUD reconnects.
- While physical Map Mode is active, v24.36's persistent OBD reconnection and 5Hz speed sampling remain unchanged. GPS remains the last fallback.

## Test and release instructions

1. Upload/import the full ZIP to the existing `saraheom/hud-drive-cross-platform-controller` GitHub repository; do not replace repository Actions secrets.
2. Run **iOS CI**, then the existing **iOS 26 TestFlight** GitHub Actions workflow.
3. In Vehicle, select **Current + Nav** and repeat the MLK / Sweetbriar drive *without interacting with the app while moving*. Observe `SPEED CURRENT NAV` logs and note when a posted limit becomes unknown versus a confirmed match.
4. Confirm the Free Ride baseline by switching back to **Current** on a separate drive if desired.
5. At the end of the drive, check that OBD recovery stops after physical HUD Bluetooth disconnect.
