# HUD Controller v90.35.3.24.16 — One-Drive Live Map Forensic Recorder

Pair with the **existing U2W v8.31 Navigation-Priority Raw MainVideo image**. No adapter reflash is required.

## Why this build exists

The September 30 field run reproduced the unresolved failure: the v8.31 relay can be reachable and the iPhone can receive raw MainVideo data while the app preview still has no usable live map image, then a later OEM-display transition (for example the head unit switching to the backup camera while parking) can make live map video appear and advance temporarily.

v24.16 is therefore diagnostic-first. Its goal is to make **one normal drive sufficient for the next root-cause patch** by preserving synchronized evidence across every layer rather than adding another narrow probe.

## What is captured automatically

The new iPhone-side `LiveMapDiagnosticRecorder` is passive with respect to CarPlay. It receives a copy of the exact bytes already delivered by the production v8.31 TCP/15332 worker **before Annex-B parsing**.

Storage is bounded:

- first **8 MiB** of the raw MainVideo TCP stream;
- rolling **4 MiB pre-event** buffer;
- up to **six** evidence windows, each preserving approximately 4 MiB before + 4 MiB after a trigger;
- final **4 MiB** raw tail at export;
- first decoded frame, decoded recovery frames, final app preview, and the last successfully delivered physical-HUD JPEG when available;
- timestamped JSONL timeline with raw byte offsets, transport phases, decoder state changes, periodic H.264/filter/VideoToolbox heartbeats, and evidence-drop reporting.

Automatic evidence-window triggers include:

- first decoded VideoToolbox frame;
- decoder recovery requests;
- fresh raw H.264 with stale decoded output;
- VideoToolbox error/recovery diagnostics;
- raw TCP read failure or EOF;
- v8.31 raw-source silence;
- decoded output resuming after a multi-second gap.

The recorder uses a chunked rolling buffer rather than repeatedly copying the whole 4 MiB history, limiting diagnostic overhead during the drive.

## Adapter-side evidence

When Route Guidance reaches the adapter, v24.16 ensures the existing **low-frequency passive v8.27.2 source/topology observer** is running. It is read-only: it does not start MainVideo, hook/signal/restart `AppleCarPlay`, or change Route Guidance/Navigation ownership.

The large adapter evidence download is **parked-only**. `Collect Live Map Diagnostic ZIP (parked)` best-effort adds:

- `u2wvideo-relay-status.cgi`;
- `u2wvideo-status.cgi`;
- `u2whud-status.cgi`;
- `u2wrgd-live.cgi`;
- `u2wvideo-diag-status.cgi`;
- `U2W_MainVideo_Passive_Diagnostic.tar.gz` from `u2wvideo-diag-bundle.cgi`, when that endpoint is available.

Failure to retrieve any adapter-side item does not block ZIP creation because the iPhone-side raw evidence is primary.

## One-tap ZIP contents

The generated ZIP contains, when available:

- `timeline.jsonl`;
- `raw_startup_first_8MiB.h264`;
- `event_*.h264` bounded pre/post failure/recovery windows;
- `raw_tail_last_4MiB.h264`;
- `images/*.jpg` decoded/HUD evidence;
- `HUD_app_session.log`;
- `iphone_state.txt` final MainVideo / parser / decoder / network / HUD STA / JPEG-relay counters;
- `adapter/*` parked adapter snapshots and passive bundle;
- `README_DIAGNOSTIC.txt` with recorder statistics and capture semantics.

## Test procedure for the next commute

1. Install v90.35.3.24.16. **Keep U2W v8.31 installed; do not reflash it.**
2. Start CarPlay and Google Maps navigation normally.
3. In the HUD app, open Map Mode controls and tap **Start Live Preview (app only)** before driving. Leave it running for the entire test. This is important: it keeps TCP/15332 + the iPhone decoder alive even if physical Map Mode cannot start, so a later OEM-screen transition/recovery is captured rather than missed.
4. You may then tap **Enable Map Mode** as usual. If physical Map Mode fails closed to Navigation, leave the app-only Live Preview running and continue the normal drive.
5. Do not perform extra diagnostic actions while driving. Normal parking/reversing at the destination is useful if that naturally reproduces the display-state-triggered recovery.
6. After parking, while still connected to the adapter, open **Status & diagnostics** and tap **Collect Live Map Diagnostic ZIP (parked)** once.
7. When the Share link appears, provide that **single ZIP**. No separate HUD log, CGI status pages, or MainVideo dump should be necessary unless the bundle reports an unavailable adapter endpoint.
