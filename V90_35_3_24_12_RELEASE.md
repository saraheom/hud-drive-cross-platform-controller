# HUD Controller v90.35.3.24.12 + U2W v8.27.2 Automatic Passive Codec Diagnostic

This is the second diagnostic-only MainVideo investigation release. The prior v8.27.1 commute proved that the working v8.11 exporter stayed on the same AppleCarPlay process, fd, and Unix socket across the Nissan-screen transition. v8.27.2 therefore does **not** change the AppleCarPlay preload, selected fd, v8.27 relay, Route Guidance, Now Playing, ambient lighting, lane rendering, or HUD video relay.

## Automatic drive workflow

The iPhone automatically calls `u2wvideo-diag-start.cgi` when the adapter/Route Guidance endpoint becomes reachable (and also when HUD BLE becomes ready). The endpoint starts two independent read-only observers:

1. the existing low-frequency `/proc` topology sampler from v8.27.1; and
2. a new native ARM codec observer that tails only `/tmp/u2w_mainvideo_live.h264`.

No action is required during the drive. Map Mode should remain off for this diagnostic commute. After parking, one **Collect automatic codec diagnostic bundle** button downloads the complete archive for sharing.

## Passive codec observer

The observer uses the same H.264 syntax parsing core that was replay-validated before packaging against previously captured streams. It:

- recognizes plausible Annex-B NAL starts while ignoring invalid type-0 framing signatures;
- validates 800×480 SPS syntax and keeps SPS IDs;
- validates PPS→SPS relationships;
- parses slice `first_mb_in_slice`, `pic_parameter_set_id`, `frame_num`, and `idr_pic_id`;
- counts coherent IDR and P access units;
- tracks frame-number discontinuities without changing the source;
- preserves parameter-set state across normal v8.11 rolling-file generations;
- detects an 8-second valid-access-unit gap while source bytes are still advancing;
- automatically records bounded 256 KiB raw rings on GAP and RECOVERY transitions (up to eight event captures);
- writes a five-second health timeline and final status file.

The observer never opens AppleCarPlay fds, never sends CarPlay traffic, never signals/restarts AppleCarPlay, and never serves video to the iPhone.

## Offline validation before packaging

The exact parser source was compiled as a host replay validator and as the ARM daemon. Against historical captures:

- `U2W_MAINVIDEO_V811_DUMP (17)` (known good) produced a valid 800×480 SPS, linked PPS, 1 IDR access unit and 5,167 coherent P access units with zero frame-number discontinuities; together with the IDR this is 5,168 completed AUs. FFprobe independently reported 800×480 H.264 and 5,169 readable frames; the one-frame difference is the expected static-replay tail because the live parser only closes a NAL when the next Annex-B delimiter arrives.
- `DUMP (18)` produced no valid SPS/PPS/access units while FFprobe independently reported repeated missing/non-existing PPS and decode-slice failures.
- the 2026-09-25 `DUMP (26)` likewise produced no coherent access units in the final rolling generation, matching the end-of-drive failure-state evidence.

This is specifically designed to answer the remaining question before the final v8.30 relay: whether coherent H.264 access units remain continuously recoverable from the v8.11 mirror during a normal commute, or whether the codec stream genuinely enters long gaps.
