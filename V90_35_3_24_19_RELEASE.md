# HUD Controller v90.35.3.24.19 + U2W v8.32

This paired release is based on the Oct. 1 field capture plus the Sept. 21 v8.24 sustained-success comparison.

## MainVideo
- Adds U2W v8.32 `U2WH2649` support.
- Rejects false type-5 candidates unless IDR slices are intra-coded and `frame_num == 0`.
- On v8.32 decoder/reference corruption, clears the poisoned iPhone codec epoch and performs **one** TCP/15332 reconnect to request the adapter's bounded current-generation checkpoint.
- A failed checkpoint is not replayed in a reconnect loop; the client stays attached and waits for a newer genuine IDR.
- No AppleCarPlay restart, signal, source selector, or Route Guidance change.

## Physical Map Mode
- Once physical mode 6 and the JPEG relay are established, stale/failed MainVideo no longer tears down Map Mode.
- The compositor remains on the fallback canvas while live video is recovering and swaps back to live imagery when decoded frames resume.
- Existing TCP/15331 first-JPEG gate and bounded connection watchdog remain intact.

## U2W v8.32
- v8.31-style on-demand process lifecycle and installer safety gates.
- v8.27-style strict passive H.264 validation.
- 1.5 MiB hard-capped current-generation checkpoint inspired by the successful v8.24 bounded-catchup path.
- One startup forward scan of only the current v8.11 mirror; no archived generation scans or repeated reseeding.
- Static BSS ~2.31 MiB; no dynamic/unbounded GOP cache.
- Safe rollback image restores exact v8.31.

## Unchanged
Route Guidance, Now Playing, HUD reboot navigation reassert, ambient-light behavior, speed-limit logic, OBD diagnostics, and production GPS speed source are unchanged. OBD speed replacement remains a later stage after live-map validation.
