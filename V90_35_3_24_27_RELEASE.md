# HUD Controller v90.35.3.24.27 — Staged Decoder Recovery + Current HUD Viewer Health

This build keeps the already-installed U2W v8.37 adapter tree unchanged. It is an app-only reliability iteration based on the October 7 field drive.

## MainVideo reliability

- Retains the v24.26 foreign-reference sanitizer guard.
- Replaces immediate destructive recovery after three `codecBadDataErr (-8969)` events with a bounded grace window: up to 24 validated access units or 2.0 seconds.
- During the grace window the existing VideoToolbox session/reference chain remains alive. A successful image callback cancels recovery.
- A naturally arriving IDR is already armed for an atomic rebuild, without destroying the current decoder first.
- Only sustained failure after the grace budget escalates to the existing hard-reset / fresh-IDR path.
- Known lifecycle `-12903` events no longer consume the reserved 8 MiB pre + 8 MiB post first-corruption evidence window.

## Physical Map Mode re-entry

- Current-session readiness now requires `hud_mjpeg_established=YES` in addition to the current session having seen a client and sent a live frame.
- After Map Mode becomes ready, the app continues polling `u2whud-status.cgi` every two seconds.
- Two consecutive checks showing the current HUD MJPEG viewer is no longer established trigger the existing bounded viewer-recovery routine.
- Historical `session_client_seen/session_live_frame_sent` latches can no longer keep a dead viewer falsely marked ready.

## Unchanged safety boundary

- U2W v8.37 unchanged.
- v8.34 hard-bounded mirror unchanged.
- exact v8.31 raw relay unchanged.
- no CarPlay/Route Guidance restart or signal injection.
- OBD ownership handoff unchanged.
- Map Mode FPS remains capped at 15.
