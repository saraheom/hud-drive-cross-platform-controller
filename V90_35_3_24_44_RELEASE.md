# HUD Controller v90.35.3.24.44 — Current + Nav road-acquisition audit reliability

Based on v24.43 (including the mid-drive H.264 read-only recovery and approved U-turn/roundabout assets). **No U2W firmware, OBD polling, Map Mode rendering, or maneuver artwork changes.**

## Evidence from the October 28 drive

Current + Nav's route-active sign coverage was 40 of 201 render samples (including 10 startup inherited-limit samples; 30 of the 191 subsequent samples). 620 of 667 logged road rejections were missing local cache coverage. The new name-only audit recorded ten attempts, none successful: seven timeouts, two HTTP 400 responses at approximately 25.6s and 37.0s, and one HTTP 502. These are failures to inspect the road inventory, **not evidence of missing speed tags**. Actual direct OSM posted-speed matches were recorded on Ridge Ave, Falls Rd, MLK Drive, and N 34th St.

## Changes in v24.44

1. **Targeted 170m named-road query**: Audit uses production `CurrentNavOSMQuery.namedRoadAudit` to query only ways whose `name` contains a distinctive normalized token. Examples: `N 34th St` → `34th`, `Powelton Ave` → `powelton`, `MLK Dr` → `luther`. The Overpass QL query uses supported case-insensitive tag regex syntax (`[name~"...",i]`) with a server limit of 50 seconds rather than requesting every nearby named and referenced way with a 25s cap. The bounded audit runs on the first unresolved street, independently of waiting for the initial 400m download. Unrecognized/ambiguous names produce an explicit unsupported-query log and never a guessed speed.
2. **Audit resilience**: Backoff is independent of primary downloads (120s, up to 10min). Failed audit requests rotate to the other configured Overpass endpoint, avoiding repeated immediate attempts against the same failed server. Primary Current + Nav still uses the original Current lightweight 400m maxspeed query and its unchanged URLSession behavior; no increased unbounded traffic.
3. **Explain HTTP 400**: `fetchCurrentNavOSM` now logs a sanitized/truncated HTTP error-body excerpt, so an Overpass parser error and a query runtime timeout are distinguishable in the next log. HTTP 200 JSON `remark` errors are rejected instead of cached as valid geographic coverage.
4. **Geographically honest persistence**: A 170m audit no longer marks 385m of coverage as verified. Each cached tile retains its actual query radius (400m speed-tag primary or 170m name audit). Legacy disk-cache entries without a radius continue to decode as 400m for backward compatibility. Nearby full-radius tiles preserve their broader footprint when merged with an audit response.
5. **Unchanged safety rules**: A speed-limit sign is shown only if CarPlay current-street identity, nearby geometry, and actual explicit OSM speed evidence agree. No inferred Philadelphia 25mph fallback, no Philly GIS integration, and no adjacent-highway borrowing. No speed sign or `Unknown` label when unresolved.

## Tests and practical limits

- Native compiled Swift policy replay covers query strings, name normalization, cache radius and legacy decoding policy, error-body logging, and rejecting Schuylkill Expressway for MLK Drive. It uses synthetic responses, not a claim that public Overpass is currently reachable.
- The older Current engine's request/matching functions remain untouched; OBD, video, maneuver assets and all U2W files are identical to v24.43.
- GitHub Actions iOS CI/Xcode compilation and on-device network access still need verification. **No public Overpass backend can guarantee 100% availability during every drive**, so if request or cache coverage remains limited, an offline/alternate source may ultimately be necessary; the planned Philadelphia GIS comparison is deliberately not in this build.
