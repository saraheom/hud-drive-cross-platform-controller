# v90.35.3.24.13 + U2W v8.30 — reference-chain MainVideo + stale Route Guidance protection

This release moves the MainVideo work from passive diagnostics to the production path while retaining the exact known-safe v8.11 AppleCarPlay exporter.

## MainVideo

- U2W v8.30 is a standalone native TCP/15332 relay; it does not replace, signal, restart, or inject AppleCarPlay.
- It validates the real 800×480 H.264 SPS/PPS/slice chain in the mixed v8.11 mirror and rejects transport/framing false positives.
- Parser and codec/reference state survive ordinary v8.11 mirror rotations.
- A bounded 12 MiB in-memory complete current reference chain (SPS + PPS + IDR + all dependent slices) exists only to synchronize an initially late iPhone client. It is never used as repeated decoder-error replay. If it expires, the relay waits for a fresh live IDR rather than replaying a partial chain.
- The iPhone begins MainVideo predecode at app-session startup and keeps the decoder warm while Map Mode is off and across HUD BLE loss.
- Isolated VideoToolbox `codecBadDataErr (-8969)` drops only the bad access unit and preserves the current reference chain. Repeated nonfatal errors arm an atomic decoder replacement for a future validated IDR; `kVTInvalidSessionErr (-12903)` remains a true hard-session failure.

## Route Guidance stall regression

The September 26 field log captured Google Maps Route Guidance sequence 1428 remaining at Adams Ave / 15 m after a short HTTP timeout while GPS showed the car had already turned and continued moving. Successful HTTP transport therefore does not prove guidance freshness.

The app now declares one source stale only when all of the following agree: unchanged sequence for at least 10 s, active normal route, maneuver distance 1–45 m, vehicle speed at least 7 mph, and three consecutive confirmations. It then releases the obsolete maneuver and continues polling. Any fresh sequence automatically restores navigation ownership. Unchanged sequences at stoplights do not trip this rule.

The U2W Route Guidance v8.8 shim and its 0x5200/0x5201/0x5202/0x5204 negotiation are unchanged in v8.30.
