# v90.35.3.24.6.1 — deep OBD speed probe v3 on the v8.25 MainVideo baseline

This is an **iOS app-only diagnostic follow-up** to v90.35.3.24.6. The paired adapter remains **U2W v8.25 Validated GOP Recovery** byte-for-byte unchanged. The MainVideo recovery implementation, HUD JPEG/MJPEG path, Route Guidance, Now Playing, speed-limit engine, ambient-light production logic, and Map Mode renderer are unchanged from v90.35.3.24.6.

## OBD speed probe v3

The prior v2 road test confirmed that standard Mode 01 PID `0x0D` is advertised but that the hidden stock item-10 refresh does not expose a simple phone-facing speed scalar. v3 therefore stops looking only for values already numerically close to mph/km/h.

When **Run 90 s OBD deep probe v3** is started from the Map Mode diagnostics card, the app:

- requires the existing HUD-managed OBD connection;
- keeps the custom Map Mode GPS speed visible and leaves full-screen Map Mode unchanged;
- reasserts hidden stock `OBD_DRIVING_VELOCITY` item 10 every 3 seconds behind the full-screen Map Mode layer;
- records a bounded 12,000 HUD→iPhone RX-frame sample set in memory rather than logging every frame live;
- records simultaneous GPS reference points;
- explicitly searches payloads for binary `41 0D xx` and ASCII `410Dxx` OBD responses;
- evaluates u8, u16 BE/LE, u32 BE/LE, and BCD fields;
- tests lags from -2.0 to +2.0 seconds;
- fits scale + offset regression to GPS speed, reporting R² and RMSE so km/h, mph, deci-units, or other linearly encoded speed fields can be detected;
- rejects constant/non-varying values such as the previously observed fixed `6`;
- writes `OBD DEEP SUMMARY`, `OBD DEEP CANDIDATE`, and optional `OBD DEEP PID410D` entries to the normal HUD log; and
- saves a shareable `HUD_OBD_SpeedProbeV3_<timestamp>.txt` report containing the top candidates, frame-key statistics, direct PID hits, and the bounded raw sample set.

The probe never opens a second iPhone→OBD connection and never sends raw ELM327 or PID requests. This keeps the OBD experiment isolated from the live-map v8.25 validation.

## Recommended road test

1. Flash/retain U2W v8.25 and install this app.
2. Start Map Mode and confirm MainVideo preflight is live.
3. Use 10 FPS for the first combined MainVideo test.
4. Once moving through several speeds, tap **Run 90 s OBD deep probe v3** once.
5. Continue the drive normally; do not run v2 at the same time.
6. After the probe completes, the ordinary HUD log is sufficient for first-pass analysis. The v3 report is optional but useful for deeper offline inspection.
7. After parking, optionally tap **Request latest HUD OBD logs** and share the returned ZIP/raw capture if available.

## Future paths if v3 finds no phone-facing speed field

- reverse engineer the HUD Android-side OBD service/binary over ADB to locate its ELM/`010D` transport and any local IPC;
- perform a parked-only direct BLE GATT discovery against the OBD adapter after temporarily releasing the HUD-owned connection;
- if the HUD itself has the numeric value but never sends it to iOS, add a small HUD-side bridge that publishes the local OBD speed over the existing vehicle LAN.
