# HUD Controller v90.35.3.24.39 — Current + Nav Road Availability and Accuracy

Built from **v90.35.3.24.38 CI FIX1**. This is a full iOS 26 GitHub repository ZIP. U2W v8.40 and the MainVideo pipeline are unchanged.

## What this release fixes

The October 22–25 logs exposed very low posted-speed sign availability in Current + Nav. The main cause was expensive uncached public Overpass queries repeatedly returning HTTP 502 or timing out. A secondary cause was strict heading rejection around turns, while some confirmed streets genuinely lacked an OSM speed tag.

### Persistent road geometry cache

- Save real downloaded OSM road geometries, names/refs and explicit speed tags in an on-device **Application Support** JSON cache (`CurrentNavOSMRoadCache-v1.json`).
- Retain up to **128 geographically bounded snapshots for 72 hours**, and restore across normal app relaunches. Use data only within **165 m** of a saved query center, plus overlapping nearby snapshots for connected-road continuity; it is *not* a full offline regional map.
- JSON encoding/writing occurs on a serial utility queue, not the HUD video-rendering actor; atomic replacement prevents partial files.
- Cache-derived speed limits are **display-only**; overspeed warnings require a direct named-road OSM speed tag acquired during the current app session and refreshed within **30 minutes**.
- When a queried area has never been cached, it still requires a successful online lookup. No speed is invented for an untagged road.

### Lighter, more resilient Overpass acquisition

- Reduce Current + Nav query radius from **430 m to 260 m** and fetch drivable ways with an OSM **name or route ref** (including ways lacking `maxspeed`). Unnamed and unreferenced roads cannot satisfy CarPlay Current Street name verification, so they are unnecessary to this lookup.
- Primary endpoint: `overpass.private.coffee`; alternate: `overpass-api.de`. On an error, try the other *on the next scheduled attempt*, not an immediate duplicate request.
- Exponential retry delay **45 seconds, 90 seconds, 180 seconds ... capped at 12 minutes** after consecutive failures. Short cooldown after success, and **30-minute revalidation** for covered areas.
- Retain a valid geographically relevant cache on network errors or malformed/empty service replies.

### Road identity, turns and legally defensible signs

- Maintain **strict CarPlay street-name/ref match** and true road-segment geometry distance. A closer Schuylkill Expressway cannot donate 50 mph to Sweetbriar Drive or MLK Drive.
- Allow modest GPS heading disagreement (**up to 82°**) when the confirmed road is within **14 m**; if recent course truly changed at a turn, allow **up to 105° within 16 m**. This does not relax street-name matching or overall corridor bounds.
- Adjacent same-name way gaps of up to **20 m** can participate in same-road connected posted-speed consensus. Conflicting tags continue to resolve as unknown.
- Accept matching explicit `maxspeed:forward` and `maxspeed:backward` only when **both directions agree**, avoiding unjustified one-way inference.
- Brief stale active navigation data does not immediately reactivate the geometry-only motorway fallback; warnings from held values remain OFF.
- Diagnostics now report cache HIT/MISS, server/HTTP errors and backoff, named-candidate heading, road identity and reasons for rejection.

## Test instructions

1. Import this full repository and run the iOS CI workflow before the TestFlight workflow.
2. Keep **Current + Nav** selected; no U2W update is needed.
3. For the first run in a new area, allow online road acquisition. On a later pass/relaunch, search the exported app log for `SPEED CURRENT NAV CACHE` **HIT** and `SPEED CURRENT NAV QUERY` **SUCCESS/FAILED**.
4. Compare verified-road sign availability, missing-sign gaps and rejected-road diagnostic details on MLK/Sweetbriar, Ridge Ave and another known route.
5. Never interpret a cached posted-speed sign as official ground truth: observe actual posted road signs for driving decisions.
