# HUD Controller v90.35.3.24.20 + U2W v8.33 — Lossless Mirror Root-Cause Fix

This paired release moves the MainVideo fix upstream to the byte-copy defect isolated from the Oct. 2 field capture.

## Root cause addressed

The exact v8.11 passive MainVideo mirror could discard bytes at its 12 MiB rolling-file boundary. If the AppleCarPlay write that triggered rotation contained continuation bytes before the first SPS/Annex-B start, v8.11 truncated the live mirror and copied only from that start code. The real AppleCarPlay write had already succeeded, so OEM CarPlay remained healthy while the mirrored H.264 stream could lose the tail of a reference picture. That matches the observed pattern of healthy CarPlay/exporter activity followed by `frame_num` discontinuity and VideoToolbox `-8969`.

## U2W v8.33

- Derived from the exact proven v8.11 mirror source; source selection is unchanged.
- Real AppleCarPlay traffic is written first and is never modified by the mirror.
- Rotation writes the **entire successful AppleCarPlay buffer** into a temporary next-generation inode and atomically renames it over the live path.
- If that atomic rotation cannot complete, the entire buffer is appended to the old generation instead of dropping bytes.
- Regular mirror writes use a write-all loop.
- `writev`/`sendmsg` mirror only the bytes actually returned by the real call.
- TCP/15332 is the **exact v8.31 32-KiB raw relay**: no adapter parser, checkpoint/GOP cache, source reacquisition, or autostart.
- No AppleCarPlay/ARMiPhoneIAP2 process control and no Route Guidance/Now Playing changes.

## App v24.20

- Preserves v24.19's fallback-first physical Map Mode: mode 6/JPEG rendering remains active when MainVideo is stale.
- Preserves strict rejection of malformed/false type-5 IDR candidates.
- A single `frame_num` jump is now a diagnostic warning rather than an automatic decoder-epoch teardown. The validated frame is forwarded and repeated VideoToolbox `codecBadDataErr (-8969)` remains the authoritative hard-recovery trigger.
- Recognizes v8.33 status and records mirror generation/rotation/fallback/preserved-prefix/write-retry counters in diagnostics.
- No ambient-light, speed-limit, lane, Route Guidance, Now Playing, HUD canvas, or production OBD-speed changes.

## First field validation

Do not intentionally trigger the reverse camera. Start the system normally. The purpose of the drive is to cross multiple v8.33 mirror rotations and verify that decoded live frames continue without `-8969`/reference loss. If the live stream still fails, leave the state untouched until parked and collect one Live Map Diagnostic ZIP.
