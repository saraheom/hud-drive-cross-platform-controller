# HUD Controller v90.35.3.24.25 + U2W v8.37 Forensic Seam Capture

## Purpose

This is the next evidence-driven MainVideo reliability build after the October 5 v24.24/v8.36 road test. It intentionally does **not** add another speculative recovery or keyframe-injection mechanism. The goal is to capture the first real failure with enough byte-level evidence to determine where the reference-chain discontinuity is introduced, while fixing the independent OBD ownership race seen when leaving Map Mode.

## What the latest drive proved

The recovered v24.24 log contains a concrete H.264 reference-continuity failure:

- decoded reference sequence progressed normally through `frame_num=3868`;
- the next accepted reference jumped to `4094`, then back to `3869`;
- VideoToolbox immediately began returning `codecBadDataErr (-8969)` callbacks;
- the TCP stream continued receiving raw bytes while decoded output remained frozen;
- a later fresh SPS/PPS/IDR restored decoding.

That separates the failure from a simple Wi-Fi/TCP disconnect. It is consistent with a corrupted, skipped, duplicated, or cross-generation H.264 reference chain somewhere around a MainVideo generation transition. v8.36 confirmed many mirror generation changes, but its text-only seam samples were not complete enough to prove which side of the adapter/iPhone boundary introduced the bad sequence.

## v8.37: passive binary generation-seam evidence

U2W v8.37 is a **diagnostic-only sidecar** over the already-installed v8.36/v8.35/v8.34/v8.31 stack.

It does not replace or modify:

- v8.34 hard-bounded mirror — expected SHA-1 `b982322ee65fd45405ab40f98512dbd76450976b`
- exact v8.31 raw relay — expected SHA-1 `b3964792342f9bc5ad22eaeb70eaf84ec04562f6`
- v8.35 helper
- AppleCarPlay / ARMiPhoneIAP2 / fakeiOSDevice
- Route Guidance / Now Playing / HUD JPEG relay

At every `/tmp/u2w_mainvideo_live.h264` inode transition, v8.37 keeps its own **read-only** old-generation fd open and saves:

- binary 4096-byte old-generation tail;
- binary 4096-byte new-generation head;
- SHA-1 fingerprints for both samples;
- old/new generation, inode, and size metadata;
- the raw relay's visible fd/offset/inode/size snapshot;
- current mirror status;
- passive `/proc` IPC/socket topology.

The newest 128 seam groups are retained. Parked collection exposes `u2wvideo-forensic-status.cgi`, `u2wvideo-seam-log.cgi`, and `u2wvideo-forensic-bundle.cgi`.

The installer verifies the exact v8.34 mirror and v8.31 relay hashes before it installs anything. It restarts only the diagnostic seam observer; it never restarts or signals the relay or CarPlay processes.

## v24.25: first-failure iPhone evidence

The iPhone recorder now reserves a fault capture specifically for the **first actual failure signal**. Normal startup/first-frame/collection events cannot consume this slot.

New evidence includes:

- `FIRST_FAILURE_*_pre8MiB_post8MiB.h264` — 8 MiB before + 8 MiB after the first failure;
- `rolling_raw/` — four bounded 4 MiB raw TCP segments retained continuously;
- raw checkpoints with byte count, FNV-1a fingerprint, and 64-byte head/tail samples;
- parser/decoder fingerprints when continuity warnings, `-8969`, `-12903`, TCP EOF, or TCP failures occur;
- `COMPLETENESS_REPORT.txt` stating exactly which evidence was captured;
- automatic parked download of the v8.37 forensic adapter bundle into the same Live Map diagnostic ZIP.

The normal v24.24 4 MiB pre/4 MiB post evidence windows are retained separately.

## OBD ownership race fix

The v24.24 drive also showed that OBD speed itself worked correctly in Map Mode, but leaving Map Mode could leave the iPhone owning or reclaiming the single-client ELM327 after Navigation resumed.

v24.25 fixes the handoff as an ownership-generation problem:

1. every production iPhone OBD connect is tagged with the current Map Mode ownership generation;
2. ending Map Mode increments the generation, invalidating all outstanding production connects;
3. in-flight connects are cancelled but their generation tags are retained until CoreBluetooth reports the callback;
4. a late `didConnect` from an old generation is rejected **before GATT discovery** and immediately cancelled;
5. a cancellation-pending set tracks BLE disconnect/failure acknowledgements;
6. the HUD OBD auto-connect loop resumes only after the bounded release barrier confirms no iPhone connection remains, or after timeout with stale callbacks still generation-gated.

The direct ELM path continues to poll only standard `01 0D`; it sends no `ATZ`, `ATSP`, reset, or protocol-selection commands.

## Deliberately unchanged

- Physical Map Mode remains fallback-first and can continue on the static canvas when MainVideo is unavailable.
- Navigation / Route Guidance remains independent of MainVideo.
- The v8.35 SOCK_DGRAM keyframe path remains installed only for rollback provenance and is **deferred** while the v8.37/v8.36 passive observer is active; the stock stream IPC framing has not been proven.
- No AppleCarPlay/ARMiPhoneIAP2 process restart, signal, or source-reacquisition loop is added.
- Existing lane-clear, ETA AM/PM, speed-warning, ambient-light, and Map Mode UI behavior is retained.
