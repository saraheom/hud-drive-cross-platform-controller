# HUD Controller v90.35.3.24.33 — automatic Map Mode and cold-start readiness

**Paired U2W:** v8.40 Resource-Safe Bootstrap (unchanged, reflash NOT required if already installed).

## 1. Persistent automatic Map Mode
- Replaced the transient "Enable/Disable Map Mode" button with **Automatic Map Mode** switch in the everyday Map Mode card.
- Desired ON/OFF preference stored in UserDefaults (`HUD.MapMode.autoEnabled`), separate from actual relay/session state. Defaults OFF on first install; once selected ON it persists across HUD BLE/car power cycles.
- After HUD BLE transport becomes ready, a single debounced automatic start waits five seconds for HUD profile rehydration to settle, then uses the existing authenticated SSID/password and **existing physical Map Mode startup flow**.
- On disconnect, cancel outstanding startup and reset one-attempt-per-BLE-session guard; retain saved preference. No MainVideo or mode-6 attempt is made without BLE connectivity or when firmware maintenance is active.
- OFF stops the physical Map Mode session and falls back to stock Navigation/Free Ride. A failure does not silently flip the saved preference OFF. OFF->ON is an explicit retry.
- UI reports desired state independently from actual H.264 status.

## 2. iPhone Shortcuts / Action Button
- Added three native background-capable App Intents, "Enable HUD Map Mode", "Disable HUD Map Mode", "Toggle HUD Map Mode".
- Actions persist the same desired-state key used by the UI, and immediately reconcile an active in-process `AppState` when available.
- Assign **Toggle HUD Map Mode** using Settings > Action Button > Shortcut; alternatively use Accessibility > Touch > Back Tap. Lock/power button remapping is not supported by iOS.
- Important: Shortcuts can update the saved preference while backgrounded, but iOS does not guarantee that a force-quit or terminated app can complete the BLE/Wi-Fi/video handoff immediately. It will apply when the app can run and the HUD transport is available.

## 3. Cold-start resilience from Oct. 18 drive evidence
- MainVideo preflight previously reused an unconfirmed `false` result during the 5s relay ensure cooldown. During cooldown, retries now read fresh relay status without reissuing the relay start request.
- Spaced failed preflight checks by 2s then 3s, allowing adapter readiness to settle. No adapter video producer, H.264 sanitizer, or decoder architecture change.
- HUD Wi-Fi STA join has a longer observation interval before its *single* automatic credential refresh and bounded mode4->mode6 recovery, supporting slower association/DHCP after car restart.
- Startup/disconnect tasks use generation guards; no overlapping auto-starts, and a late task cannot overwrite a newer attempt's state.

## 4. Live source unavailable: black/empty map
- `HudMapModeCanvas.mapBlock` renders `Color.black` instead of `HudMapModeSchematic` when source image is missing; real speed, speed-limit and live guidance overlays continue independently.
- Phone preview also rejects stale H.264 frames (>1.5s) rather than showing the last frozen source image.

## 5. ETA
- Explicit `.foregroundStyle(.white)` on the shared ETA label fixes a likely black-on-black visibility defect even when `shouldRenderETA` was already true.
- Adds a low-frequency `MAP ETA` renderer heartbeat with showETA, route, lane count, shared position, text, and canvas coordinate. Does not interfere with Route Guidance or lane rendering.

## 6. Navigation startup load
- Stops automatically downloading the legacy MainVideo codec/topology diagnostic when Route Guidance first becomes reachable. The parked **Collect Live Map Diagnostic ZIP** action and existing read-only diagnostic endpoints remain available.
- No claim is made that all first-maneuver audio/video startup lag has been eliminated; this is a conservative workload reduction pending drive validation.

## Suggested field test
1. Keep U2W v8.40 installed. Build/install the new full GitHub repo using existing iOS CI/TestFlight workflow.
2. Enter adapter SSID/password under Map Mode once and set **Automatic Map Mode** ON.
3. Shut the car fully off; on the next start with the HUD and adapter back online, confirm mode 6 re-enters automatically (allow longer Wi-Fi DHCP settling). Navigation should remain usable while connecting.
4. Lock the iPhone and change apps during the trip. Confirm live map continuity is unchanged.
5. End route: live CarPlay map remains visible; if video is unavailable, map area is black, not the former dummy schematic.
6. Start routes with and without lane guidance and confirm white ETA at the shared lane location when the lanes are absent. If not, collect diagnostics with `MAP ETA` lines.
7. Assign Toggle HUD Map Mode in Shortcuts to the iPhone Action Button; test OFF => standard Navigation and ON => Map Mode.
8. After arriving, perform a full car-off second trip and collect live map diagnostic ZIP if startup still fails.
