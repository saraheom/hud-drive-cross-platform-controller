# HUD Controller v90.35.3.24.3 — physical HUD stale-lane renderer reset

This release is based on v90.35.3.24.2 and carries forward its dual U2W v8.24 TCP wire-handshake compatibility (`U2WH2642` + `U2WH2643`) unchanged.

## Field evidence

The 2026-09-20 drive log captured a lane event on maneuver 8 and then a maneuver transition 8 → 9 where CarPlay reported `laneGuidanceShowing=false`. The app correctly cleared its Map Mode lane state and transmitted three native empty-lane packets to the physical HUD:

- `Lane guidance clear`
- `Lane policy → post-maneuver clear`
- `Lane policy → post-maneuver settle clear`

The physical HUD nevertheless retained the previous lane graphic in one observed case. This isolates the remaining defect to stale state inside the stock HUD Navigation renderer rather than CarPlay lane parsing or the app preview.

## Fix

When a lane policy clear ends a real lane payload while Navigation is active:

1. Send the normal native `laneCount=0` clear immediately.
2. After 90 ms, if no newer lane generation has appeared, re-apply the user's normal Navigation dashboard. The stock launcher creates a fresh Navigation widget instance.
3. Re-send the current maneuver to hydrate the fresh renderer.
4. After another 180 ms, if the same no-lane generation is still current, send one final `laneCount=0` clear.

The sequence is generation-guarded and cancelled by new lane data, HUD BLE disconnect, or lane-session replacement. It therefore cannot erase a newer valid lane event that arrives during the short recovery window.

## Unchanged

- U2W v8.24 firmware and relay binaries/scripts
- MainVideo v90.35.3.24.2 dual-wire handshake compatibility
- VideoToolbox / software-decode recovery behavior
- Center/BLEDOM ambient day/night behavior
- CarPlay lane parsing and Map Mode lane rendering

No U2W reflash is required for this app release.
