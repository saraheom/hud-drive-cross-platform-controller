# HUD Controller v90.35.3.24.26 — Foreign Reference Guard + Compact Map Mode UI

## Scope

This is an **app-only corrective release** for the already-installed **U2W v8.37 Forensic Seam Capture** stack. Do not reflash the adapter for this update.

The October 6 v24.25/v8.37 field capture isolated the immediate decoder poison event while the adapter mirror and TCP byte flow remained alive. Immediately before VideoToolbox failed, the established reference sequence was interrupted by a syntactically plausible foreign P-slice:

- normal epoch reference priority: `nal_ref_idc=1`
- normal sequence around failure: `... 3169 → 3170 → 3171 ...`
- contaminant: `frame_num=3999`, `nal_ref_idc=2`, P-slice
- captured contaminant SHA-1: `07063717b6f7ace70ac8fd3ab8a75d5333cfcf4a`
- immediate result: repeated VideoToolbox `codecBadDataErr (-8969)` and decoder recovery

The v8.37 seam evidence did not identify a coincident mirror-generation break, so v24.26 makes no adapter transport change.

## Targeted MainVideo correction

`H264MainVideoSanitizer` now learns the normal reference priority from accepted reference P-pictures in the active validated IDR epoch. A VCL candidate is rejected before VideoToolbox only when **both** conditions are true:

1. its `nal_ref_idc` differs from the learned reference priority, and
2. its `frame_num` is not the expected next reference frame.

When this guard fires:

- the candidate is not forwarded to VideoToolbox;
- it does not advance `lastReferenceFrameNum`;
- the next real reference picture can continue from the pre-contaminant state;
- the event is recorded as `FOREIGN_REF_IDC_REJECT`;
- it does not itself trigger the hard decoder-recovery path.

This rule is intentionally narrower than a blanket `nal_ref_idc` filter. A priority change on the expected next frame remains legal, and same-priority frame-number gaps remain telemetry because the field captures also contained benign missing pictures that decoded successfully.

## UI cleanup

The field diagnostics remain available in the collected ZIP, but routine controls are simplified:

- **Vehicle → Map Mode OBD** now shows one compact ownership/connection status instead of the Direct ELM feasibility/probe panel.
- **Map Mode Status & diagnostics** disclosure is removed.
- **Stream** status remains as a small line.
- **Map Mode FPS** is directly accessible and remains the proven set: `5 / 8 / 10 / 12 / 15` fps.
- **Collect Live Map Diagnostic ZIP (parked)** is directly accessible on the Map Mode page.

No 20/25-fps modes are added in this release.

## OBD behavior

The v24.25 ownership-generation and bounded CoreBluetooth release-barrier implementation is retained. The October 6 drive completed the Map Mode ↔ HUD OBD ownership handoff automatically without manual intervention, so v24.26 does not alter that mechanism.

## U2W boundary
