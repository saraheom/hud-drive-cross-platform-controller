# HUD Controller v90.35.3.24.28 — Mid-Drive Continuity Guard

Paired with existing U2W v8.37. No adapter reflash is required.

## Purpose

This release targets every mid-drive live-map interruption class identified in the Oct. 7 field logs while intentionally leaving startup bootstrap for the next isolated step.

## Runtime changes

### 1. Generalized one-picture H.264 continuity quarantine

The production MainVideo path now uses `H264MainVideoSanitizer.processBatch(_:)`.

A first-slice P picture with a *gross* circular `frame_num` jump is held for one-picture look-ahead instead of being immediately submitted to VideoToolbox. Small gaps remain telemetry and continue to flow.

This directly covers both field contaminant shapes:

- `3170 -> 3999 -> 3171` (foreign reference priority)
- `2239 -> 1151 -> 2240` (`nal_ref_idc=0` contaminant)

If the next genuine picture resumes the old cadence, only the held candidate is dropped and continuity state is not advanced. If the grossly shifted cadence persists, dependent P pictures are quarantined until a validated IDR rather than poisoning VideoToolbox.

The previous `FOREIGN_REF_IDC_REJECT` protection remains as an additional diagnostic/protection layer.

### 2. Ordinary scene inactive/background no longer destroys VideoToolbox

v24.27 intentionally invalidated VideoToolbox on ordinary iOS scene transitions. Field logs showed that this manufactured WAITING_FRESH_IDR outages at approximately 5:39 PM and 5:49 PM even though MainVideo TCP remained healthy.

v24.28 preserves:

- MainVideo TCP
- Annex-B parser state
- validated SPS/PPS
- VideoToolbox session
- H.264 reference chain

through ordinary inactive/background notifications. A genuine `kVTInvalidSessionErr (-12903)` is still handled by the existing bounded decoder-recovery path.

### 3. Staged codecBadData recovery retained

The v24.27 bounded grace path remains unchanged as a fallback:

- `CODEC_BAD_DATA_GRACE_ARMED`
- successful output -> `CODEC_BAD_DATA_GRACE_RECOVERED`
- sustained failure -> `CODEC_BAD_DATA_GRACE_EXHAUSTED` and hard recovery

Prevention now occurs before this fallback whenever a gross off-cadence candidate is identified.

### 4. Failure recorder reservation corrected

Generic lifecycle/watchdog decoder-recovery callbacks can no longer reserve the large corruption-only first-failure window. Concrete codec/transport failure signals still own that capture path.

### 5. Map Mode viewer/session fix retained

The v24.27 current-HUD-viewer health monitoring and Map Mode re-entry fix are unchanged.
