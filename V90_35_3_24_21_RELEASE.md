# HUD Controller v90.35.3.24.21 + U2W v8.34

## Purpose

This paired release combines the next MainVideo reliability fix with a passive whole-drive OBD diagnostic recorder.

### MainVideo: hard-bounded mirror resource fix

The 2026-10-02 evening field run showed v8.33 starting and decoding normally without a reverse-camera transition, then failing when its nominal 12 MiB mirror generation had grown to ~48.6 MiB because rotation still waited for another SPS. MainVideo, Route Guidance JSON, CGI/status, and the custom relay failed together while AppleCarPlay remained alive. v8.34 addresses that shared `/tmp` resource failure mode directly.

- 8 MiB hard generation cap, independent of SPS/IDR cadence.
- Rotation only between successful AppleCarPlay write calls; complete current write starts the next generation.
- Atomic next-inode replacement; no H.264 parser/GOP cache needed for rotation.
- write-all mirror writes and exact real-return-byte handling for vectored writes.
- If bounded rotation itself fails, the resource guard disables only the passive MainVideo mirror rather than growing `/tmp` without bound.
- Selected MainVideo FD can passively unlatch when that exact FD closes and later relatch on a genuine SPS-bearing FD.
- Exact v8.31 32-KiB raw TCP/15332 relay retained.
- No AppleCarPlay/ARMiPhoneIAP2 process control, no source-selector mutation, no historical scan/cache, and no MainVideo autostart.
- Status exposes `/tmp` free space, mirror sizes, hard rotations, resource-guard trips, and FD lifecycle counters.

The iPhone keeps the v24.20 decoder policy: a single `frame_num` discontinuity is diagnostic telemetry rather than automatic stream quarantine; repeated real VideoToolbox failures remain the hard-recovery signal. Physical Map Mode stays fallback-first and independent of MainVideo availability.

### OBD: automatic whole-drive passive flight recorder

The previous v4 item-10 probe established that PID 0x0D is advertised by the HUD/OBD stack but the repeated hidden-item stimulus does not expose a speed-varying HUD event. The parked stock diagnostic request also returned mismatched/malformed categories such as `LOG_CATEGORY_CRUSH` instead of a trustworthy `LOG_CATEGORY_OBD` archive.

v24.21 therefore stops relying on that 90-second active probe as the primary workflow and records the actual HUD transport passively for the full drive:

- recorder starts automatically when the existing HUD OBD connection is reported;
- no second OBD connection is opened;
- no repeated hidden-item-10 stimulus is sent by this workflow;
- every HUD BLE notification is written before protocol parsing/de-duplication;
- every app->HUD TX packet labeled OBD-related is recorded;
- simultaneous GPS reference speed and OBD connection-state events are recorded;
- transient HUD BLE disconnects are logged without discarding the existing drive session;
- the parked collection action separately attempts the stock `LOG_CATEGORY_OBD` transfer for up to 45 seconds, preserving raw/mismatched data rather than trusting its category;
- one final `HUD_OBD_DriveDiagnostic_v90.35.3.24.21_*.zip` contains the drive capture, GPS reference, state timeline, app session log, and any stock-log artifacts.

Production displayed vehicle speed remains **GPS**. OBD speed will not be enabled until a real field is identified and validated against the GPS reference across a drive.

## Field test

1. Flash U2W v8.34 and let the adapter reboot normally.
2. Install the v24.21 app/TestFlight build.
3. Drive normally with Google Maps/CarPlay. Do not intentionally trigger reverse-camera transitions for MainVideo startup.
4. Leave Map Mode/live map running if practical. The key MainVideo validation is survival across repeated hard mirror rotations with healthy `/tmp` headroom.
5. The OBD flight recorder starts automatically after the HUD reports its existing OBD connection; no 90-second probe is needed.
6. After parking while the HUD remains powered/connected, tap **Collect OBD Drive Diagnostic ZIP (parked)** once and share that ZIP if OBD analysis is needed.
7. If MainVideo fails, also collect the normal Live Map Diagnostic ZIP before power loss when possible.
